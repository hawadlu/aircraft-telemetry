## Why this exists

You said the thing you're most worried about is **communication**:

1. **Posting something to serial** — a fake telemetry source you can point at your serial bridge.
2. **Reading fake sensors from the Pico, with accurate pin selection** — to prove the wiring/bus setup before the real sensors arrive.

These tools do exactly those two things and nothing clever. They let you exercise the serial path and the Pico pin map **without** waiting on hardware, and **without** writing any of the learning-critical code for you.

## Quickstart A — host only, no hardware (do this first)

Prove the serial round-trip on the Mac alone using a virtual serial pair.

```bash
# 1) Create a linked pair of virtual serial ports. Leave this running.
socat -d -d pty,raw,echo=0 pty,raw,echo=0
#    It prints two device paths, e.g.  /dev/ttys010  and  /dev/ttys011

# 2) Second terminal — read from one end:
python serial_monitor.py --port /dev/ttys011

# 3) Third terminal — write fake telemetry to the other end:
python serial_telemetry_source.py --port /dev/ttys010 --hz 2
```

The monitor prints validated lines. Try replay mode to see the gap/bad-line handling:

```bash
python serial_telemetry_source.py --port /dev/ttys010 --mode replay --file sample_flight.ndjson
# monitor flags: a sequence gap (seq 5 missing) and one malformed JSON line
```

Point `serial_telemetry_source.py` at one end of the `socat` pair and point **your bridge** (labs 07.3/07.4) at the other end. Now you can build the serial bridge against a known-good stream before any firmware exists.

### `serial_telemetry_source.py`

| Flag | Default | Meaning |
|---|---|---|
| `--port` | *(required)* | serial device (`/dev/tty.usbmodemXXXX` or `/dev/ttysNNN`) |
| `--baud` | `115200` | baud rate |

| `--drop` | `0.0` | 0–1 probability of dropping a message (simulate packet loss) |
| `--count` | `0` | stop after N messages (0 = forever) |

| Flag | Default | Meaning |
|---|---|---|
| `--port` | *(required)* | serial device |
| `--baud` | `115200` | baud rate |

Prints `ok`/`x` per line, flags malformed JSON and sequence gaps, and totals good/bad on exit.

## Pico setup (MicroPython)

1. **Flash MicroPython:** download the Raspberry Pi Pico UF2 from [micropython.org/download/RPI_PICO](https://micropython.org/download/RPI_PICO/). Hold **BOOTSEL**, plug the Pico into USB (it mounts as `RPI-RP2`), drag the `.uf2` onto it. It reboots running MicroPython.
2. **Copy the three Pico files** to the device. Easiest with `mpremote` (`pip install mpremote`):
   ```bash
   mpremote connect /dev/tty.usbmodemXXXX fs cp pin_map.py fake_sensors.py main_fake_telemetry.py :
   ```
   (Or use [Thonny](https://thonny.org): open each file, *File → Save as → Raspberry Pi Pico*.)
3. **Run it** — two options:
   - One-off, output to your terminal: `mpremote connect /dev/tty.usbmodemXXXX run main_fake_telemetry.py`
   - Auto-run on boot: save `main_fake_telemetry.py` to the Pico as **`main.py`**, then power-cycle. Now `serial_monitor.py` / your bridge can read the stream.

> **REPL caveat:** MicroPython's REPL shares the USB serial port, so a banner may appear once on reset. Running as `main.py` (or via `mpremote run`) keeps the NDJSON stream clean for a consumer.

### Pin map (airborne Pico)

Baked into `pin_map.py`, matching the hardware you own and [`../components/README.md`](../components/README.md) §8. **Verify against your final wiring.**

| Function | Interface | Pico pins | Source |
|---|---|---|---|
| IMU + baro (+ future AHRS, digital airspeed) | I2C1 | **SDA GP6, SCL GP7** | Waveshare 10DOF-IMU default |
| 10DOF interrupts (optional) | digital | ICM INT **GP4**, LPS INT **GP5**, FSYNC **GP22** | Waveshare 10DOF-IMU default |
| GPS | UART0 | **TX GP0, RX GP1** | components §6.3 / §8 |
| Telemetry radio (UART path) | UART1 | **TX GP8, RX GP9** | components §5 / §8 |
| Battery voltage | ADC0 | **GP26** | components §8 |
| Analog airspeed (only if MPXV7002) | ADC1 | **GP27** | components §8 |
| Status LED | digital | onboard **GP25**, spare **GP14** | components §6.5 |

⚠️ **LCD caveat:** this assumes the **Pico-LCD-1.14 is *not* stacked on the airborne payload** (it occupies GP8–13 and GP2/3/15/16/17/18/20). Keep the LCD on the bench/ground side. If you stack it airborne, the UART1 radio pins (GP8/GP9) clash — re-pin the radio first.

## Implementing a real sensor (interface cookbook)

`fake_sensors.py` returns invented numbers, but it initialises each interface **for real**. To turn any sensor from fake into real:

1. **Read the datasheet** and identify the interface — **I2C, SPI, UART, analog (ADC), PWM/pulse, or digital IO** — plus its address / baud / transfer function.
2. **Copy the matching pattern below**, wired to a free pin (see the pin map).
3. **Replace the fake body** of the relevant `read_*` method with the real read.
4. **Keep returning a dict** so `build_message` in `main_fake_telemetry.py` can merge it.

> Pico facts: ADC is **GP26/27/28 only**, 0–3.3 V (`read_u16()` → 0..65535). There are 2× I2C, 2× SPI, 2× UART; **every** GPIO can do PWM; digital IO + interrupts on any pin.

### I2C — e.g. ICM-20948 IMU, LPS22HB baro, BNO08x, MS4525DO airspeed
```python
from machine import Pin, I2C
i2c = I2C(1, sda=Pin(6), scl=Pin(7), freq=400_000)
i2c.scan()                               # confirm the address from the datasheet
data = i2c.readfrom_mem(0x68, 0x2D, 6)   # addr, register, n bytes (per datasheet)
```
→ `read_imu` / `read_baro`. Datasheet gives: 7-bit address, register map, scaling.

### SPI — some high-rate IMUs (also the LCD and the SPI-radio option)
```python
from machine import Pin, SPI
spi = SPI(0, baudrate=1_000_000, sck=Pin(18), mosi=Pin(19), miso=Pin(16))  # example pins
cs = Pin(17, Pin.OUT, value=1)
cs(0); spi.write(b"\x80"); resp = spi.read(2); cs(1)   # CS low, transfer, CS high
```
Datasheet gives: SPI mode (CPOL/CPHA), max clock, the read/write bit convention.

### UART — e.g. GPS, SiK/Ebyte radio
```python
from machine import Pin, UART
uart = UART(0, baudrate=9600, tx=Pin(0), rx=Pin(1))
line = uart.readline()        # e.g. one NMEA sentence from the GPS
```
→ `read_gps`. Datasheet/protocol gives: baud, and the sentence/packet format to parse.

### Analog (ADC) — e.g. analog airspeed MPXV7002DP, potentiometer, analog temp
```python
from machine import Pin, ADC
adc = ADC(Pin(27))                  # GP26/27/28 only
volts = adc.read_u16() / 65535 * 3.3
```
→ `read_analog_aux`. Datasheet gives the volts→units curve. **Anything that can exceed 3.3 V (e.g. MPXV7002 on a 5 V rail) must go through a divider first** (components §8).

### PWM / pulse input — e.g. RC channels, some rangefinders/airflow sensors
```python
from machine import Pin, time_pulse_us
sig = Pin(17, Pin.IN)
pulse_us = time_pulse_us(sig, 1, 30000)   # measure HIGH pulse, 30 ms timeout
# pulse_us < 0  => timeout / no signal
```
→ `read_pwm_input`. Datasheet gives the frequency and the pulse-width→units mapping. For many channels or tight timing, use a pin IRQ to timestamp edges, or PIO.

### Digital IO — e.g. switch, hall digital out, 'data ready'/INT line, GPS PPS
```python
from machine import Pin
flag = Pin(16, Pin.IN, Pin.PULL_UP)    # pull-up/down per datasheet
asserted = flag.value() == 0           # active-low example
flag.irq(trigger=Pin.IRQ_FALLING, handler=lambda p: ...)   # event-driven alternative
```
→ `read_digital`. Datasheet gives active-high vs active-low and pull requirements.

### PWM output — not a sensor, but you have servos
```python
from machine import Pin, PWM
servo = PWM(Pin(20)); servo.freq(50)              # 50 Hz frame
servo.duty_u16(int(1500 / 20000 * 65535))         # 1500 us = centre
```

The analog / PWM / digital patterns already have working stubs in `fake_sensors.py`
(`read_analog_aux`, `read_pwm_input`, `read_digital`) on example pins **GP27 / GP17 / GP16**.
Swap the fake body for the real read, then merge the result in `build_message`.

## Troubleshooting

- **`pyserial not installed`** → `pip install -r requirements.txt`.
- **Permission denied / port busy** → close Thonny/other serial monitors; only one program can own a port.
- **No such file `/dev/ttysNNN`** → use the exact paths `socat` printed; they change each run.
- **Monitor shows nothing** → check both ends use the same `--baud`; confirm the source is writing to the *other* end of the `socat` pair.
- **Garbage from the Pico** → that one-off REPL banner; run as `main.py` or via `mpremote run`.
